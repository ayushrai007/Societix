# SOC-100 — Chart of accounts and double-entry ledger tables

Creates the accounting foundation from [SOC-100's prompt](../../codegen/prompts/backend/SOC-100-chart-of-accounts-and-double-entry-ledge.md)
and [dd-01](../../archive/deep-dives/dd-01-double-entry-ledger.md): integer-paise journal lines,
database-enforced balanced postings, append-only history, and four statutory equity funds per society.

## Touched files and modules

- `backend/src/main/resources/db/migration/V7__create_ledger.sql`: accounts, journal headers/entries,
  minimal accounting-period metadata, tenant-qualified foreign keys, forced RLS, restricted grants,
  deferred balance checks, immutability triggers, and fund seeding at migration and society creation.
- `backend/src/test/java/com/societix/LedgerIT.java`: PostgreSQL Testcontainers acceptance coverage.

## Verification

Run `./mvnw -B verify` from `backend/` with Java 25 and Docker. Focused suite:
`./mvnw -B verify -Dtest=FlywayMigrationTest -Dit.test=LedgerIT`.

Acceptance mapping (all methods are in `LedgerIT`):

1. Tables via migration: `migrationCreatesLedgerTablesWithForcedRlsAndRestrictedRuntimeRole`.
2. Equal debits/credits: `balancedPostingCommitsAndDuplicateEventIsRejected`,
   `unbalancedAndEmptyPostingsFailAtCommitAndRollBack`, and
   `invalidLinesAndLaterUnbalancedInsertsAreRejected`.
3. Fund seeds: `standardFundsAreSeededForExistingAndNewSocietiesIdempotently` upgrades a database
   containing a society at V3, then checks both that society and one onboarded after V7.
4. Isolation: `societiesCannotReadOrWriteEachOthersLedgerAndMissingContextFailsClosed` checks every
   new table and rejects cross-society inserts/references. Connections use SOC-10's runtime login,
   never `SET ROLE`. Each transaction sets `set_config('app.tenant_id', ?, true)` (equivalent to
   `SET LOCAL`), exactly as SOC-10 tests do. Missing, empty, and malformed contexts expose no rows.
5. Append-only permissions: `postedHeadersAndEntriesCannotBeUpdatedOrDeleted`.

Verification status: all sources compile and both Modulith checks pass on Temurin 25.0.5.
Full `verify` is blocked before integration tests: Testcontainers cannot find `/var/run/docker.sock`.

## Configuration, decisions, and limits

- No dependency or tool-version changes. The existing Testcontainers setup provisions both roles;
  Flyway alone uses its owner connection. Backfill runs through a temporary, narrowly privileged
  security-definer function owned by the no-login RLS-bypass role. Runtime seed functions retain
  invoker privileges. `LedgerMigrationRoleIT` proves V7 deploys under a non-superuser, non-BYPASSRLS
  database-owner migration role that is a member of the no-login role (the helper needs temporary
  `CREATE` on `public` to receive ownership, and `SELECT` on `ledger_account` for `ON CONFLICT`).
- Commit checks cover headers and later line inserts; empty or context-hidden journals also fail.
  Accounting-period metadata preserves dd-01's required reference; period-close workflows,
  posting services, events/outbox consumers, reports, and reversal APIs remain future work.
- SOC-5 and SOC-10 are merged foundations. SOC-13 request-level binding to the logged-in user is
  explicitly deferred; it depends on SOC-11 login. This build does not implement either task.
- Self-review: scope, tenant isolation, database idempotency, integer amounts, and secret handling
  reviewed. No HTTP interface/logging is added. PostgreSQL acceptance results remain unverified.
